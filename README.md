# Cloud Rail

Cloud Rail is the name I use for work that has to arrive the same way twice.

A rail is a fixed path. The cloud is where that path ends. I took the handle because the useful part of my job is the unglamorous middle: a change leaves a laptop, stays on a track, and shows up in production without anyone having to remember the steps.

## Background

I learned systems by breaking small Linux machines and putting them back. The first work that stuck was keeping a handful of web apps online for a shop that had no operations person. Evenings were package updates, disk alerts, and deploy scripts that only I understood. I got tired of being the script.

I still work independently, and I work remotely. Most days are deployment pipelines, small tools with one job, and reading other people's systems code when a failure does not match the dashboard. I keep GitHub on Bangkok time because that is the day I actually work.

The account number on this handle is just a disambiguator. The name is the rail.

## What I pay attention to

- A deploy that can be repeated by someone who was not in the room when it was written
- A rollback that is a command, not a meeting
- Logs that say which change went out, not only that something is red
- Tools small enough to read in one sitting
